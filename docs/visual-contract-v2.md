# 配图契约 v2：给 AITutor-APPLE 的几何规格

> 2026-08-25 · Node 版 `dev` 分支已落地。配套 content-v2.2。
> 契约本体：`data/curriculum/visual-contract.json`（`sync-skills.sh` 拉包时一并带走，
> 出到 `curriculum/visual-contract.json`）。这份文档只讲**为什么**和**怎么画**，
> 机器可读的范围和规则以 JSON 为准。

## 0. 一句话

课程 `steps[].visual` 的图型白名单、每种图的 `nums` 约定、合法范围，从今天起**只有一份**，
就是那个 JSON。两端的渲染器、我们的 preflight、你们的 `LessonValidator` 都读它。
同时加了两种以前画不出来的图（假分数、数轴上的分数），并且把「越界怎么办」统一成一种。

## 1. 为什么要立这份契约

你们在 content-v2.2 需求书里已经点破了一半：白名单数目在三个地方各说各话（36 / 39 / 41）。
我们查下来另一半更要命——**两端对越界的处理不一样**：

- 我们（web）**静默钳位**：`fractionBar [3,4]` 里分子 4 被钳成 3，画出一条满格的 3/3，
  而那一步的课文正在说「三分之四比一整条还多」。图和话对着干。
- 你们（Apple）**降级成无图**：同一份数据，孩子那边什么都看不到。

同一份 JSON 两种坏法，谁都不知道孩子实际看到了什么。看图模式上线之后这事从「小瑕疵」
变成「屏幕上唯一那句话在解释一张画错的图」。

顺手量出来的现网存量（`data/lessons` 全库 4546 步、3599 步有图）：

| 症状 | 步数 | 屏幕上是什么 |
|---|---|---|
| 比 1 大的分数画不了，靠「一整条 + 余数」两张图凑 | 15 | 两张图各标 `4/4`、`3/4`，「7/4」从头到尾没出现过 |
| 数轴打不出分数刻度，点标成小数 | 44 | 图注写「四分之三和十二分之九同一个点」，画面上是 **0.75** |
| `placeValue` 六位以上直接 return ""，整步空图 | 31 | 讲「十万位、百万位」的课，一张图都没有 |
| `nums` 越界被钳/被截，画出数字错的图 | 3 | 5 组 68 个点、8 段被截成 6 段…… |

前三类都不是「缺图」，所以**一条都不在 content-v2.2 那 685 行 CSV 里**——CSV 统计的是
`visual.type == "none"`，而这些步 type 都不是 none。

## 2. v2 新增的两种画法

契约 JSON 里有 `capabilities` 段，每种带 `since: 2`。**只实现到 v1 的客户端遇到它们必须
降级成无图，千万别按 v1 的老办法硬画**（分子会被钳到分母，正好把课讲反）。

### 2.1 `improperFraction` — `fractionBar` / `pie` 认分子 > 分母

**编码**：就是最自然的 `[3, 4]` = 三分之四。不用再拆成 `[3,3,3,1]` 去凑。

**画法**（fractionBar，画布 460×H，左右留白 pad=14，条形总宽 bw=350）：

```
wholes = ceil(n / d)                       // 占几个整体，契约上限 4
wGap   = 6                                 // 整体之间的缝，让「一个整体」看得出边界
unit   = (bw - (wMax - 1) * wGap) / wMax   // 一个整体的宽度
cw     = unit / d                          // 一格的宽度
```

- `wMax` = 这张图里**所有条**的 wholes 的最大值。两条一起画时整体宽度按它取齐——
  不然「同一个整体」在图上就成了假话，而那恰恰是这些课要教的。
- 从左到右第 k 格（跨整体连续计数）涂色当且仅当 `k < n`。
- **同一条里所有涂色格同色**；两条之间才换色（第一条 `#ff8a5b`，第二条 `#6c8cff`）。
- 右侧只标一次 `n/d`（如 `4/3`），不要每个整体各标一次。

**pie 同理**：`ceil(n/d)` 个整圆连排，同色，**整组正中间**只标一次 `n/d`。
同一个量的圆间距 138，两个量之间 190（视觉上区分「这是一个数」和「这是两个数在比」）。

> 为什么要求同色 + 单标签：现网那 15 步的绕法之所以读不懂，就是因为两张异色、各带标签的图，
> 和这些课里「上下两条 = 比大小」的固定句式撞了。同色单标签是把「加」和「比」在视觉上分开。

### 2.2 `numberLineSubdivision` — 数轴认分数

**编码**：`nums = [最小值, 最大值, 点1, 点2, 每单位小份数]`，第 5 个数是新增的。
只有一个点时把它写两遍占位（`[0, 1, 0.75, 0.75, 4]`）——`nums` 只能装数字，没法填 null。

**画法**：

- 每一整格再平分 `den` 份，在非整数位置打**短刻度**（半高，`y±4`，1.2px）；整数刻度照旧（`y±6`，2px）。
- **整数刻度才标数字**。span=1 时原来强制画两段（0 / 0.5 / 1），分数课上冒出 0.5 是不对的；
  给了 den 就只标 0 和 1。
- 标记点标成**分数**：整数部分在左（15px，粗），分数竖着摞在右（分子 11px / 横线 12px 宽 / 分母 11px）。
  纯 SVG 文字 + 一条线，不用 LaTeX，两端都画得出来。
- **给了 den 就不画跳跃箭头**：给分母的场景是比大小，两个点各自标好分数即可
  （原来的 `+0.08` 箭头在分数课上没有意义）。
- **标记点必须正好落在某根 1/den 刻度上**，落不到就是违约 → 不画。图注承诺了格子，图上就得有格子。

### 2.3 顺手修的 `placeValue`

位值表原来卡在 `n >= 100000 return ""`，而 `PV1M` / `PVBIG` 两组课讲的就是六位到十位数——
31 步整步空图。位值标签表扩到十亿位（`个位…十亿位` / `Ones…Billions`），上限提到 `1e10`。
不是新能力，是补回本来就该有的。

## 3. 越界怎么办：统一成「不画」

我们把 web 端的静默钳位改掉了，改成和你们一致：**违约 → 降级成无图**。
理由就是你们需求书里那句「宁可不配图，也不能配错图」——看图模式下图是正文，
画错严格差于不画。从此同一份数据在两端只有一种失败方式，preflight 的结论对两端同时成立。

判定代码是 `public/visual-check.js`，浏览器 `<script src>` 和 node `require()` 用的是**同一个文件**
（不是两份实现）。规则种类见契约 JSON 的 `rules` 段：`lenIn / int / range / rangeAll / le / lt /
inSpan / wholes / count / sum / snapFrac / positive / statSeries`，一共 13 种，都很好移植。

## 4. 我们这边的验收

```bash
node tools/curriculum/visual_check.mjs            # 全库 preflight，违约退出码 1
node tools/curriculum/visual_check.mjs --dir build/apple-export/lessons
```

现状：**4546 步 / 3599 步有图，零违约**（含「有图但 caption 为空」这一条，v2.2 §五 那 9 处已补）。
建议你们同步之后也跑一遍，两边结论应当一致；不一致就是有一端没照契约走。

## 5. 还没做、留给 v2.3 的

- **不等大的整体**（大饼的 1/4 vs 小饼的 1/2）：bar 固定 350 宽、pie 固定 R=62，两端都画不出
  两个不一样大的整体。`zh EQUIV.SAME_WHOLE #3` 认了 headline-only。
- **44 步数轴 + 15 步假分数的回写**：契约和渲染能力都就位了，但内容要等**两端都实现 v2** 才能放，
  否则你们那边会整片降级成无图。这批是纯 `visual` / `caption` 改动，`say` 不动，零语音成本。
- 试点里 `zh EQUIV.MULTIPLY #4` 现在用的是两端今天都画得出来的 `[3,2,3,3]`（三分之二 对 一整条）；
  你们上了 `improperFraction` 之后，它应该升级成 `[3,2,3,4]`（三分之二 对 三分之四），
  那才是这一步课文真正在讲的那句话。
